# 2026/09/10 작업내용

렌더러 전체를 훑어보고 문제점과 설계 지점을 정리한 분석 문서(`docs/rendering-analysis.html`)를 먼저 만들었고, 거기서 뽑은 0단계 항목들을 이번에 처리했다. 새 기능보다는 기반 정리 위주.

## 진행한 작업

### 1. 깊이 버퍼 추가

- `m_DSView`가 선언만 되어 있고 어디서도 생성되지 않아 깊이 테스트가 아예 없던 상태였음. 지금까지 구 하나가 제대로 보인 건 볼록한 단일 물체에 후면 컬링이 켜져 있어서였을 뿐.
- `Device`에 `CreateDepthStencilView()`와 `BindRenderTargets()` 추가.
    1. 깊이 텍스처는 `D24_UNORM_S8_UINT`, 크기와 샘플 수를 백버퍼와 일치시킴
    2. 기존에는 `CreateRenderTargetView()`가 생성과 `OMSetRenderTargets`를 같이 했는데, 바인딩을 분리해서 RTV와 DSV가 둘 다 준비된 뒤 한 번에 걸도록 변경
    3. Resize 경로에서도 RTV와 같이 해제하고 재생성
    4. `Device::Clear()`에 `ClearDepthStencilView` 추가
- DepthStencilState는 일부러 만들지 않았다. D3D11 기본값이 이미 깊이 테스트 켜짐 / LESS / 쓰기 허용이라 DSV만 걸리면 동작하고, 명시적 상태 객체는 다음 단계 PSO가 소유해야 할 물건이라 지금 개별 호출로 넣으면 나중에 걷어내야 한다.

### 2. 프레임당 Clear 중복 제거

- `AppBase::Run()`과 `Renderer::Render()`가 각각 `Device::Clear()`를 불러 프레임당 두 번 클리어하고 있었음. 지금은 무해하지만 두 Clear 사이에 스카이박스나 배경 패스를 그리기 시작하면 두 번째가 지워버린다.
- `Renderer` 쪽 Clear 제거. 클리어 색 상수도 `Device::Clear()` 한 곳만 남기고 쓰이지 않던 `g_ClearColor` 삭제.

### 3. ComPtr로 통일

- `Device`만 `ComPtr`을 쓰고 `Shader`, `MeshRenderer`, `Renderer`는 생 포인터 + `SafeRelease`를 쓰던 걸 전부 `ComPtr`로 통일. `helper.h` 삭제.
- 규칙을 한 줄로 정함. **소유하면 ComPtr, 생 포인터면 소유하지 않음.** `Device*`, `Shader*`, `Camera*` 같은 역참조와 게터 반환값은 생 포인터 유지.
- `Device`의 생성 함수는 이중 포인터 출력 인자에서 `ComPtr<T>` 값 반환으로 변경. 나중에 RHI에서 핸들을 반환하는 형태로 옮기기 자연스러운 쪽을 골랐다.

```cpp
// 이전
void CreateConstBuffer(int size, ID3D11Buffer** ppCB);

// 이후
ComPtr<ID3D11Buffer> CreateConstBuffer(UINT size);
ComPtr<ID3D11Buffer> CreateVertexBuffer(const void* pData, UINT size, UINT stride);
ComPtr<ID3D11Buffer> CreateIndexBuffer(const void* pData, UINT size);
ComPtr<ID3D11InputLayout> CreateInputLayout(const D3D11_INPUT_ELEMENT_DESC* desc, UINT num, ID3DBlob* pVSCode);
```

- 전환하면서 제일 조심한 부분이 `GetAddressOf()`와 `ReleaseAndGetAddressOf()` 구분. 기준은 **API가 그 자리에 값을 쓰느냐 읽느냐**.
    1. 출력 인자(`T**`)에는 `ReleaseAndGetAddressOf()` — `CreateRasterizerState`, `CreateTexture2D` 등
    2. 입력 배열(`T* const*`)에는 `GetAddressOf()` — `VSSetConstantBuffers`, `IASetVertexBuffers`, `OMSetRenderTargets`
    3. 단일 인자에는 `Get()` — `VSSetShader`, `IASetIndexBuffer` 등
- 2번에 `ReleaseAndGetAddressOf()`를 쓰면 바인딩 직전에 버퍼가 해제되고 널이 걸린다. 컴파일은 통과해서 눈으로 걸러야 하는 자리.

### 4. 셰이더 컴파일 오류 메시지

- 에러 Blob을 읽지 않고 버리고 있었고, `std::cout`에 `const TCHAR*`를 그대로 넘겨서 파일 경로 자리에 포인터 주소가 찍히고 있었다.

```
// 이전
[실패] 셰이더 컴파일 실패 : 파일 경로 : 00007FF65550B370 진입점 : VS_Main 타깃 : vs_5_0

// 이후
[실패] 셰이더 컴파일 실패 : 파일 경로 : BasicVertexShader.hlsl 진입점 : VS_Main 타깃 : vs_5_0
BasicVertexShader.hlsl(13,5-10): error X3000: unrecognized identifier 'flaot4'
```

- Blob이 아예 없으면 대체로 파일을 못 찾은 경우라 HRESULT를 사람이 읽는 문장으로 보여주도록 처리.
- Debug 빌드에 `D3DCOMPILE_DEBUG | D3DCOMPILE_SKIP_OPTIMIZATION`, Release에 `D3DCOMPILE_OPTIMIZATION_LEVEL3` 적용. RenderDoc에서 HLSL 원본을 따라가려면 필요하다.

### 5. Release 빌드 복구

- HLSL의 `ExcludedFromBuild`가 `Debug|x64`에만 걸려 있어서 다른 구성에서는 MSBuild가 셰이더를 기본 진입점 `main`으로 컴파일하려다 `error X3501`로 실패하고 있었다.
- 셰이더는 런타임에 `D3DCompileFromFile`로 컴파일하므로 빌드할 때 FXC를 돌릴 이유가 없다. 조건을 없애고 전 구성에서 제외.
- 겸사겸사 `LanguageStandard`와 PCH 설정도 `Debug|x64`에만 있던 걸 발견. Release가 조용히 C++14로, PCH 없이 빌드되고 있었다. 네 구성 모두 `stdcpp17` + PCH로 통일.

### 6. PCH 정리와 전역 using namespace 제거

- `pch.h`가 48줄에서 30줄로. SpriteBatch, SpriteFont, WICTextureLoader, DDSTextureLoader, CommonStates, DirectXTex를 include하면서 어느 것도 쓰지 않고 있었다. 실행 파일이 해당 DLL을 import하지도 않는 걸로 확인.
- SimpleMath도 같이 삭제. `Vector3`, `Matrix` 같은 타입이 코드에 한 번도 안 나왔다. 수학 타입은 **DirectXMath로 확정**.
- 진짜 문제였던 `using namespace DirectX;`를 헤더에서 제거.
    1. 헤더 6개는 `DirectX::` 접두어를 붙임
    2. .cpp 6개는 include 아래에 파일 지역 `using namespace DirectX;` 한 줄
- 이제 헤더가 이름공간을 새지 않으니 나중에 자체 `Color`나 `Plane` 타입을 만들어도 모호성 오류가 안 난다.
- `struct.h`가 `enum.h`와 `DirectXMath.h`에 의존하면서 include하지 않고 `pch.h`의 순서 덕에 우연히 컴파일되던 것도 같이 고침.

### 7. 로그 파사드와 반환 규약

- `Log.h` / `Log.cpp` 추가. `std::cout` 29곳을 `Log::Info` / `Log::Warn` / `Log::Error`로 교체.
    1. 콘솔과 `OutputDebugStringW` 양쪽으로 출력. VS 출력 창에서 D3D Debug Layer 메시지와 같은 곳에 나온다
    2. `Log::HrToString(hr)`이 HRESULT를 `0x80070002 (지정된 파일을 찾을 수 없습니다.)` 형태로 변환
    3. `Log::Init()`이 `SetConsoleOutputCP(CP_UTF8)` 호출. 소스가 `/utf-8`로 컴파일되는데 콘솔은 CP949라 그동안 한글 로그가 실제로 깨지고 있었다
- 레벨 필터, 파일 싱크, ImGui 콘솔은 안 만들었다. 나중에 Logger 클래스로 바꿀 때 호출부를 다시 안 고치려고 싱글턴이 아니라 자유 함수 네임스페이스로 둠.
- 반환 규약은 **엔진 API는 bool, HRESULT는 호출 직후에 검사해서 bool로 바꿔 올린다**로 통일.

| 대상 | 이전 | 이후 |
|---|---|---|
| `Shader::Initalize` | 오타 | `Initialize` |
| `Shader::ShaderLoad()` | HRESULT 둘 버리고 무조건 true | 둘 다 검사 |
| `Shader::ShaderCreate()` | void | bool |
| `Renderer::DataLoading()` | int, 호출자가 버림 | bool, 호출자가 검사 |
| `Renderer::RasterStateCreate()` | void, HRESULT 4개 미검사 | bool, 넷 다 검사 |

### 8. vcpkg 매니페스트

- 저장소에 어떤 패키지의 어떤 버전을 쓰는지 기록이 없어서 다른 PC에서 클론하면 빌드가 안 되는 상태였다.
- 루트에 `vcpkg.json`을 두고 `VcpkgEnableManifest=true`. `builtin-baseline`으로 vcpkg 커밋 고정.
- 링커 경로가 바뀐 게 예상 밖의 소득. 전역 설치를 쓸 때는 `installed\x64-windows\lib\*.lib` 와일드카드로 이 PC에 깔린 boost 55개랑 glm까지 링커에 넘어가고 있었다.
- `.editorconfig`도 추가. C++ 소스는 UTF-8 BOM, HLSL은 BOM 없음.

## 문제 / 이슈

- 인코딩 변환할 때 HLSL에도 BOM을 붙였더니 `D3DCompileFromFile`이 `error X3000: Illegal character in shader file`로 거부했다.
- 초기화 실패가 실제로 `main`까지 올라가기 시작하니까 **종료할 때 죽었다.** 그동안은 `Initialize`가 사실상 항상 성공한 셈이라 이 경로에 도달한 적이 없었을 뿐, 원인 셋 다 예전부터 있던 문제였다.
    1. `WndProc`이 전역 `g_appBase`를 널 검사 없이 역참조
    2. `~AppBase`가 `g_appBase = nullptr`을 먼저 하고 `DestroyWindow`를 호출. `DestroyWindow`는 `WM_DESTROY`를 동기적으로 보내서 방금 널로 만든 포인터를 건드린다
    3. ImGui 초기화 여부와 무관하게 `ImGui_ImplDX11_Shutdown()`을 호출

## 해결 내용

- HLSL은 순수 ASCII라 BOM만 제거해서 원래 바이트로 복구. **C++ 소스만 BOM, HLSL은 BOM 없이**가 이 프로젝트 규칙이 됐다.
- 종료 크래시는 세 군데 다 수정.
    1. `WndProc`에 널 가드. 없으면 `DefWindowProc`으로 넘김
    2. 소멸자에서 **창을 먼저 파괴한 뒤** `g_appBase`를 지우도록 순서 변경
    3. 초기화 단계별로 bool 플래그를 남겨서 실제로 초기화한 것만 되돌리고, `MsgProc`도 그 플래그를 보고 ImGui에 넘기도록 변경

## 확인한 것

- 깊이 테스트가 화면으로는 확인이 안 된다. 구 하나에 후면 컬링이라 DSV가 있으나 없으나 결과가 같기 때문. 그래서 깊이 텍스처 높이만 절반으로 만든 실험 빌드를 따로 만들어봤더니 디버그 레이어가 정확히 그 불일치를 짚었다. 실제 DSV 치수를 읽어서 보고했다는 건 널이 아닌 뷰가 OM에 들어갔다는 뜻.

```
D3D11 ERROR: OMSetRenderTargets: The RenderTargetView at slot 0 is not
compatible with the DepthStencilView. RTV has (w:1280,h:720),
DSV has (w:1280,h:360).
```

- 누수는 수정 전 커밋을 별도 worktree에 빌드해서 A/B로 비교. 종료 시 살아남은 객체가 **D3D11 31개 / DXGI 1개에서 둘 다 0개**가 됐다.
- `vcpkg_installed/`를 통째로 지우고 빌드해서 새 클론 상황을 흉내냈고, MSBuild가 알아서 6개 패키지를 설치하고 빌드까지 마쳤다.
- Debug / Release 전체 재빌드 경고 0건. 창 크기를 여러 번 바꿔도 D3D 오류 없음.
