# 2026/10/23

## 진행한 작업
- HDR 렌더 타깃과 톤매핑 패스(이전 글) 위에 **후처리(Post Process)** 를 추가.
- 후처리: 씬을 다 그린 뒤, 완성된 화면 이미지를 입력으로 받아 **풀스크린 패스로 다시 가공**하는 단계.
- 만든 효과는 3개: 가우시안 블러, 블룸, GreyScale.
- 효과를 켜고 끄는 값은 씬 환경(`SceneEnvironment`)에 넣고, 에디터에 **단계별 결과를 썸네일로 보여 주는 창(Post Stages)** 을 추가.

![효과별 비교 (효과 끔 / GreyScale / Blur / Bloom)](/assets/img/sherlock/pp/pp-01.png)

### 1. 프레임 흐름과 효과 순서
- 순서는 엔진이 고정하고, 사용자는 효과의 켜짐/세기만 조절.

```
ShadowPass
→ MainPass            (선형 FP16 HDR 텍스처에 그림)
→ 블러 → 블룸          (HDR 값 그대로 처리)
→ TonemapPass         (노출 → ACES → GreyScale → sRGB)
→ UIPass
```

- **블러·블룸은 톤매핑 앞**: 1을 넘는 밝기가 살아 있는 선형 HDR 값에서 해야 함. 톤매핑 뒤(0~1)에서 하면 밝은 곳이 이미 눌려서 블룸이 약해짐.
- **GreyScale 같은 색 효과는 톤매핑 뒤**: 최종 화면의 색을 바꾸는 것이라 표시될 값 기준으로 하는 게 자연스러움.
- 효과의 결과는 **항상 HDR 텍스처에 다시 덮어씀**.
  - 톤매핑 패스는 효과가 몇 개 켜졌는지 몰라도 됨.
  - 효과를 추가해도 톤매핑 패스는 안 바뀜.

### 2. 공통 인프라
- 모든 후처리 패스가 **같은 바인딩 레이아웃(`Layout_Post`)** 을 공유: `b0`(PerFrame), `b4`(PostParams), `t13`(입력 텍스처), `s6`(선형 Clamp 샘플러).
- 파라미터는 새 상수 버퍼 **`PostParams`(b4, 80바이트)** 로 전달.
  - 효과가 늘면 파라미터도 늘어서 PerFrame에 섞지 않고 따로 둠.
  - 패스마다 모드와 값을 바꿔 다시 올림.

```cpp
struct alignas(16) PostParamsConstants
{
    XMFLOAT4 pass;    // x = 모드, yz = 블러 방향
    XMFLOAT4 blur;    // x = 시그마, y = 반경
    XMFLOAT4 bloom;   // x = 임계값, y = knee, z = 배율
    XMFLOAT4 view;    // xy = 입력 크기, zw = 출력 크기
    XMFLOAT4 grade;   // x = GreyScale 양, y = 색 효과 건너뜀
};
static_assert(sizeof(PostParamsConstants) == 80);
```

- 한 프레임에 `UpdateBuffer`를 여러 번 불러도 안전함.
  - 업로드 링에서 호출마다 새 조각을 할당하고, 바인딩은 draw 시점에 최신 조각을 가리킴.
- 후처리 PSO는 톤매핑 PSO 설정을 복사해서 **픽셀 셰이더와 렌더 타깃 포맷(FP16)만 교체**.
- 설정 값(`PostProcessSettings`)은 `SceneEnvironment` 안에 둠.
  - 씬 저장/로드와 에디터 Undo/Redo(씬 직렬화 방식)에 별도 작업 없이 같이 들어감.
  - 이전 씬 파일은 키가 없어도 `value(키, 기본값)`으로 효과가 꺼진 채 열림.

### 3. GreyScale
- 새 패스를 만들지 않고 **톤매핑 셰이더 끝에 한 줄** 추가 (uber 방식).
- 휘도(Rec.709 계수)를 구해서 원래 색과 `lerp`.

```hlsl
float3 color = ApplyExposureToneMap(hdr);
if (postGrade.y < 0.5f)
{
    const float luma = dot(color, float3(0.2126f, 0.7152f, 0.0722f));
    color = lerp(color, luma.xxx, saturate(postGrade.x));
}
return float4(color, 1.0f);
```

- 디버그 뷰(알베도·노멀 등)는 이 코드보다 위에서 먼저 반환하므로 흑백이 되지 않음.

### 4. 가우시안 블러
- 2D 가우시안은 **가로 한 번 + 세로 한 번**으로 나눠도 결과가 같음 (가로·세로가 독립).
  - 반경이 r이면 `(2r+1)²`번 읽을 것을 `2×(2r+1)`번으로 줄임.
- 읽는 텍스처에 동시에 쓸 수 없어서 **임시 텍스처를 거쳐 `hdr → temp → hdr`** 로 왕복.
- 가중치는 시그마에서 바로 계산하고, 가중치 합으로 나눠 밝기가 변하지 않게 함.
- 화면 밖은 좌표를 `clamp`해서 가장자리 픽셀을 반복.

```hlsl
const int radius = min((int)postBlur.y, kMaxBlurRadius);
const float invTwoSigmaSq = 0.5f / (sigma * sigma);

float3 sum = 0.0f;
float weightSum = 0.0f;
for (int i = -radius; i <= radius; ++i)
{
    const float w = exp(-(float)(i * i) * invTwoSigmaSq);
    const int2 c = clamp(base + dir * i, int2(0, 0), maxCoord);
    sum += postInput.Load(int3(c, 0)).rgb * w;
    weightSum += w;
}
return float4(sum / weightSum, 1.0f);
```

- 반경은 **720p 기준 픽셀**로 받고 출력 높이에 비례해 키움.
  - 씬 뷰 크기를 바꾸거나 작은 카메라 미리보기에서도 같은 비율로 흐려짐.
  - 시그마 = 유효 반경 / 2.5 (±2.5σ 바깥은 가중치가 거의 0이라 자름).

### 5. 블룸
- 밝은 부분이 주변으로 번지는 효과. 큰 반경의 블러를 직접 하면 비싸서 **줄이고 키우는 방식**으로 처리.

1. **밝기 추출 + 축소**: 임계값을 넘는 밝기만 남기면서 절반 크기로.
2. **축소 4번**: 계속 절반씩 (총 5레벨). 레벨이 작을수록 한 텍셀이 넓은 영역을 대표.
3. **확대 4번**: 작은 레벨부터 키우면서 **가산 블렌드(One/One)** 로 위 레벨에 더함.
4. **합성**: 최종 결과에 `intensity`를 곱해 HDR 텍스처에 더함.

```hlsl
float3 BrightPass(float3 c)
{
    const float brightness = max(c.r, max(c.g, c.b));
    float soft = clamp(brightness - threshold + knee, 0.0f, 2.0f * knee);
    soft = soft * soft / (4.0f * knee + 1e-5f);
    const float contribution = max(soft, brightness - threshold) / max(brightness, 1e-5f);
    return c * contribution;
}
```

- **knee**: 임계값 근처를 2차 곡선으로 이어서 경계가 딱 끊겨 보이지 않게 함.
- 축소는 입력 텍셀 모서리 4곳을 선형 샘플러로 읽어 **4x4 박스 평균**이 되게 함.
- 확대는 **3x3 텐트 필터** `(1 2 1 / 2 4 2 / 1 2 1) / 16`.
- 확대 출력은 알파를 0으로 내보내서 가산 블렌드가 기존 알파를 유지하게 함.

### 6. 효과 실행 함수
- `ApplyHdrEffects`가 켜진 효과만 순서대로 실행하고, 켜진 효과가 없으면 **스크래치 텍스처도 만들지 않고 패스도 기록하지 않음**(비용 0).
- 임시 텍스처(블러용 1장, 블룸 5장)는 효과가 처음 켜질 때만 만들고, 화면 크기가 바뀌면 다시 만듦.
- 카메라 미리보기도 같은 함수를 자기 텍스처로 불러서 **미리보기에도 효과가 적용**됨.

### 7. 단계별 썸네일 창 (Post Stages)
- 다른 프로그램의 단계별 결과 썸네일처럼 **Scene → Blur → Bloom → Final** 을 나란히 보여 주는 에디터 창.
- 텍스처 복사 기능이 RHI에 없어서(`CopyBuffer`만 있음) 톤매핑 패스를 **작은 텍스처에 다시 그리는 방식**.
  - 입력/출력 크기 비로 좌표를 줄여 읽음.
  - Scene/Blur/Bloom은 색 효과를 건너뛰고(그 효과가 한 일만 보이게), Final만 색 효과까지 포함.
- 창이 열려 있는 프레임에만 캡처해서 닫으면 비용이 사라짐. 꺼진 효과는 `off`로 표시.
- 창 폭에 맞춰 4칸이 같이 커지고 줄어듦.

![단계별 썸네일 창](/assets/img/sherlock/pp/pp-02.png)

## 문제 / 이슈
### 썸네일 창을 켜면 크래시
- 썸네일 텍스처를 `Render()` 안에서 (재)생성했더니 창 크기가 바뀐 프레임에 크래시.
- 원인
  1. 에디터는 UI를 먼저 만들면서 ImGui 텍스처 ID를 쥠. (D3D11에서는 이 ID가 SRV 포인터)
  2. 그 뒤 `Render()`가 같은 텍스처를 파괴하고 새로 만들면 UI 패스가 **해제된 SRV**를 그림.
- 처음에는 EXE/ABI 불일치로 추정했지만, 다시 빌드해도 6번 중 6번 재현돼서 **틀린 진단**이었음.
- 해결: 썸네일 생성/재생성을 **UI를 만드는 시점**으로 옮김. (씬 뷰 텍스처를 UI 단계에서 바꾸는 것과 같은 규칙)
  - 이후 같은 조건을 9번 반복해 모두 정상 종료.

### 그 밖에
- `std::min/max`가 Windows 매크로와 충돌(C2589) → `(std::min)(a, b)`로 감쌈.
- `SherlockEditor`/`SherlockGame`을 프로젝트 파일 단독으로 빌드하면 `EntryPoints.h`를 못 찾음 → 솔루션 전체로 빌드.

## 확인한 것
- 단계마다 스크린샷을 찍어 확인하고 넘어감.
  1. **효과를 모두 끈 화면은 변경 전과 픽셀 단위로 같음** (차이 0).
  2. GreyScale: 씬 뷰가 흑백.
  3. 블러(반경 8, 24): 화면이 흐려지고 가장자리 이상 없음.
  4. 블룸: 밝은 영역 주변이 번짐.
- D3D11과 D3D12 결과가 거의 같음 (채널 차이 최대 1). 게임 모드도 동일.
- 확인하지 못한 것: 에디터에서 슬라이더를 직접 움직이는 경우, 실제 Undo 실행, Release 빌드.

## 결론
- 후처리 구조는 **"HDR 구간 효과(블러, 블룸) → 톤매핑 → 색 효과"** 로 정리됨.
  - HDR 구간 효과: 결과를 HDR 텍스처에 덮어써서 톤매핑 패스가 모름.
  - 색 효과: 톤매핑 셰이더에 한 줄씩 추가.
- 효과 추가 순서: 설정 필드 → 직렬화 → UI → 셰이더 모드/`ApplyHdrEffects` 블록.
- 다음 작업: 톤매핑 뒤(LDR)에서 해야 하는 FXAA 같은 효과. 지금은 톤매핑이 최종 출력에 바로 써서, 톤매핑 출력을 LDR 중간 텍스처로 돌리는 구조 변경이 먼저 필요.
