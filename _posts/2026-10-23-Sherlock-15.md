# 2026/10/23

## 진행한 작업
- 씬을 **선형 HDR 텍스처(`R16G16B16A16_FLOAT`)** 에 그리고, 마지막에 **별도의 톤매핑 패스**에서 노출 → ACES → sRGB 인코딩을 하도록 구조를 바꿈.
- 이전 글의 "다음 작업"이었던 톤매핑 분리와 HDR 렌더 타깃 도입.
- 이후 블룸 같은 후처리를 얹기 위한 **기반 작업**.

![ACES 톤매핑 적용(왼쪽) / 미적용(오른쪽)](/assets/img/sherlock/hdr/hdr-01.png)

### 1. 기존 구조의 문제
- 이전 흐름: `ShadowPass → MainPass → [PreviewPass] → UIPass`.
  - 톤매핑이 **머티리얼·스카이박스 픽셀 셰이더 끝**에 있었고, 렌더 타깃은 **8비트 sRGB**.
- 문제
  1. 8비트 타깃에 쓰는 순간 **1을 넘는 값이 그 자리에서 잘림**. 이후 단계에서 밝기 정보를 쓸 수 없음.
  2. 셰이더마다 톤매핑을 넣어야 해서 **빠뜨리거나 두 번 적용**할 위험이 있음.
  3. 블룸처럼 "1을 넘는 밝은 곳"을 다뤄야 하는 후처리를 못 함.

### 2. 새 프레임 흐름
```
EnsureHdrTargets          (크기가 바뀌었을 때만 HDR 텍스처 재생성)
→ ShadowPass
→ MainPass                (선형 값을 FP16 HDR 텍스처에 그대로 씀)
→ TonemapPass             (HDR 읽기 → 노출 → ACES → sRGB 뷰로 출력)
→ PreviewPass → PreviewTonemapPass   (카메라 미리보기도 같은 경로)
→ UIPass
```

- 메인 톤매핑 패스를 프리뷰 패스보다 먼저 둠. 프리뷰가 b0(PerFrame)를 **다른 카메라 값으로 덮어쓰기 전에** 메인 톤매핑이 끝나야 하기 때문.
- 머티리얼·스카이 셰이더는 톤매핑을 하지 않고 **선형 HDR 값을 그대로 반환**.
  - 한쪽만 바꾸면 이중 적용이나 미적용이 되므로 패스 전환과 같은 시점에 같이 바꿈.
- 톤매핑 함수 호출은 `TonemapPixelShader` 한 곳뿐 (grep으로 확인).

### 3. 풀스크린 삼각형
- 톤 패스는 정점 버퍼 없이 `SV_VertexID`(0, 1, 2)만으로 **화면을 덮는 삼각형 하나**를 그림.
  - 사각형 두 개보다 삼각형 하나가 대각선 경계가 없고 정점도 적음.
- 이 정점 셰이더(`ScreenVertexShader.hlsl`)는 이후 후처리 패스들이 같이 씀.

```hlsl
float4 VS_Screen(uint vertexId : SV_VertexID) : SV_POSITION
{
    const float2 uv = float2((vertexId << 1) & 2, vertexId & 2);
    return float4(uv.x * 2.0f - 1.0f, 1.0f - uv.y * 2.0f, 0.0f, 1.0f);
}
```

### 4. 톤매핑 픽셀 셰이더
- HDR 텍스처를 **같은 픽셀 좌표로 `Load`** 해서 읽음.
  - 입출력 크기가 같아서 1:1 대응이고, 샘플러 슬롯(s0)과 겹칠 일도 없어서 샘플러를 쓰지 않음.
- 디버그 뷰(알베도 등)는 톤매핑을 거치지 않고 바로 반환.

```hlsl
float4 PS_Tonemap(float4 position : SV_POSITION) : SV_TARGET
{
    const float3 hdr = sceneHdr.Load(int3((int2)position.xy, 0)).rgb;
    if (debugParams.x > 0.5f)   // 디버그 뷰는 노출·톤매핑 없음
        return float4(saturate(hdr), 1.0f);
    return float4(ApplyExposureToneMap(hdr), 1.0f);
}
```

- 톤매핑 함수: 노출을 곱한 뒤 켜져 있으면 **ACES 근사(Narkowicz 2016)** 로 `[0, ∞)`를 `[0, 1]`로 누름.

```hlsl
float3 ApplyExposureToneMap(float3 color)
{
    color *= outputParams.x;                       // 노출
    if (outputParams.y > 0.5f)                     // ACES on/off
    {
        color = saturate((color * (2.51f * color + 0.03f)) / (color * (2.43f * color + 0.59f) + 0.14f));
    }
    return color;
}
```

- 톤매핑을 끄면 노출만 곱하고 1을 넘는 값은 출력에서 잘림.
  - 위 비교처럼 켜면 하늘의 밝은 영역이 눌려 **구름 질감이 남고**, 끄면 흰색으로 날아감.

### 5. sRGB는 톤 패스의 출력 뷰가 담당
- FP16 텍스처에는 하드웨어 sRGB 인코딩이 없음.
  - 그래서 **선형 값 그대로** HDR 텍스처에 쓰고, 톤 패스의 **sRGB 렌더 타깃 뷰**가 마지막에 한 번 인코딩.
- sRGB 텍스처는 샘플링할 때 하드웨어가 선형으로 변환하므로 셰이더 안의 계산은 모두 선형 공간.
- 톤 패스 PSO는 매 프레임 `GetTonemapPipeline()`으로 가져옴. 출력 포맷이 `R8G8B8A8_UNORM_SRGB`/`R8G8B8A8_UNORM`으로 바뀔 수 있어서.

### 6. 톤 패스용 PSO 설정
- 기존 PSO 기본값은 깊이가 있는 3D 패스용이라 풀스크린 패스에 그대로 쓰면 안 맞음.

| 항목 | 기본값 | 톤 패스 |
|---|---|---|
| cull | Back | None |
| depthEnable / depthWrite | true | false |
| dsvFormat | D24 | Unknown |

- 특히 **깊이 없는 패스에 D24 PSO를 쓰면 D3D12가 거부**하므로 `dsvFormat = Unknown`은 필수.
- 바인딩 레이아웃은 `b0(PerFrame)` + `t13(HDR 입력)`. 새 상수 구조체 없이 기존 PerFrame을 재사용.

### 7. HDR 텍스처 생성 시점
- `SetOutputSize()`는 **값만 저장**하고 텍스처를 만들지 않음.
  - 에디터가 곧 `SetSceneTarget()`으로 크기를 바꾸므로 지금 만들면 버리게 됨.
- `EnsureHdrTargets()`를 `Render()` 맨 앞에서 호출해서 **필요한 크기와 다를 때만** 다시 만듦.
  - 목표 크기: 오프스크린(에디터)이면 씬 크기, 아니면 출력 크기.
- 제약: **HDR 텍스처 크기 = 깊이 버퍼 크기 = 출력 크기**여야 함.
- 카메라 미리보기는 크기와 입력 텍스처가 달라서 **별도의 HDR 텍스처와 바인딩 셋**을 가짐.

## 문제 / 이슈
- 렌더 타깃을 8비트에서 FP16으로 바꾸니 **PSO의 렌더 타깃 포맷이 전부 달라짐**.
  - 메인 PSO와 스카이 PSO는 항상 FP16, sRGB 분기는 톤 PSO에만 남김.
- 톤매핑이 켜진 상태에서는 **unlit(감마 검증용) 재질의 "128이 화면에서 128로 읽힘" 검증이 깨짐**.
  - 감마 검증은 톤매핑을 끄고 노출 1에서 해야 함.
- 클리어 색도 이제 톤매핑·노출을 거친 값으로 보임. (의도된 변화)
- HDR 텍스처 생성에 실패하면 `Render()`가 일찍 반환하는데, D3D12에서는 백버퍼 상태 전이가 빠져 에러 로그가 날 수 있음.
- 바인딩 셋 상한 `kMaxBindingSets = 4`에 딱 맞게 쓰고 있어서, 레이아웃을 하나 더 늘리면 상한을 올려야 함.

## 확인한 것
- Debug x64 빌드 통과 (경고 0, 오류 0, 셰이더 컴파일 포함).
- D3D11 에디터 실행: 바인딩 대조 `ToneMapPS t13/b0 OK`, `HDR 텍스처 1280x670`, 패널 크기를 바꾸면 `614x294`로 **크기가 바뀔 때만 한 번씩** 로그가 나옴.
- 구체·헬멧·하늘이 정상으로 보임 (톤매핑 on, 노출 1, IBL 0.5). 오류 로그·디버그 레이어 경고 없음.
- 이 시점에 확인하지 못한 것: 이전 화면과의 픽셀 비교, D3D12 실행, 게임 모드, Release 빌드. (D3D12·게임 모드는 후처리 작업에서 확인)

## 결론
- 톤매핑이 **셰이더 끝에서 풀스크린 패스 하나로** 옮겨졌고, 씬은 1을 넘는 값이 잘리지 않는 **선형 FP16 텍스처**에 남게 됨.
- 프레임 흐름: `ShadowPass → MainPass(HDR) → TonemapPass(노출·ACES·sRGB) → UIPass`.
- 같은 풀스크린 패스 구조 위에 블룸 같은 후처리를 얹을 수 있게 됨.
